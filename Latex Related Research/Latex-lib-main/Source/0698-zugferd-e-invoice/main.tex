% SAME upstream package; only one is shipped here. LPPL-1.3c per merged.tsv;
% the shipped zugferd.sty carries only a bare copyright line with no grant
% text (the same trap flagged for other bare .sty headers in
% research/README.md), so the licence is verified instead from the GitHub
% repo's own LICENSE file (full LPPL-1.3c text, confirmed via GitHub's own
% licence detection). Ships with TeX Live (tex/latex/zugferd) -- starter does
% not bundle the class.
%
% engine.txt: lualatex. The class embeds the ZUGFeRD XML as a PDF/A-3
% attachment via the l3pdf/pdfmanagement machinery (\pdf_object_ref:n, AF
% catalog entry) -- this did not compile cleanly under pdflatex in this image,
% matching merged.tsv's own engine column.
%
% Adapted from the upstream project's own DEMO-rechnung-zugferd.tex, using the
% higher-level zugferd-invoice wrapper (KOMA-Script \letter integration)
% rather than the bare expl3 zugferd package directly. Kept as a GERMAN
% invoice rather than translated to English: the wrapper's own
% \PrintInvoiceTabular hardcodes "MwSt."/"Summe (Netto)"/"Summe (Brutto)"
% column labels and a literal € sign (\TableCurrency = \,€) regardless of the
% `currency` key or document language -- it says so itself
% ("this integrates a lot with the visual structure of your invoice... may be
% an example for your own package", ptxcd/zugferd warning on load). Setting
% currency=GBP still tags the embedded XML correctly but leaves a
% pound-denominated invoice showing German labels and a euro sign on the
% printed page, which is worse than just being honest that this wrapper is
% German-centric and building a real German invoice against it. Real content
% is an invented Hamburg IT-consulting firm's invoice, not the demo's
% placeholder "Käufer Name"/project-XX text.
\DocumentMetadata{
  pdfversion=1.7,
  pdfstandard=a-3b,
  lang=de,
}

\usepackage[format=xrechnung3.0]{zugferd-invoice}
