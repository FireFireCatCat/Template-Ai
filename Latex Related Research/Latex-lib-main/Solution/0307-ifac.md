## Verdict
The look is carried by one class, `class.ifacconf`, which is IFAC's official kit and therefore published under the rubric's W1 ruling (as eLife's kit is). The sample adds only `graphicx` and `natbib` and uses the class's own vocabulary (`frontmatter`, `\thanks[label]`, `\author[label]`, `\address[label]`, `keyword`, `ack`, `thm`, `pf`), so an emitter writes `\documentclass{ifacconf}`, two `\usepackage` lines and these wrappers with no zip-local macro logic. The sample defines no macro of its own, and no external tool is needed. Caveat for re-reading under another definition: ifacconf.cls is hand-written code that redefines kernel internals (see "Bespoke code"); if it were counted as zip-local it would be an irreducible `BESPOKE/class` and the answer would be `no`. This is evidence about the class dimension, not about the component ways.
