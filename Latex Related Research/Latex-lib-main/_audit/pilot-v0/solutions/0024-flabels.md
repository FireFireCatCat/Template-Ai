# 0024-flabels: flabels, binder spine labels (package source, doc driver on ltxdoc)

- Unverified: read from the source, not compiled.
- Source: Source/0024-flabels/ (origin: https://mirrors.ctan.org/macros/latex/contrib/flabels.zip; licence: lppl1)
- Kind: misc
- Lib: v0
- Engine: pdfLaTeX-compatible (the patched build script calls `pdflatex`, makedoc-patched:57; the original builds DVI with `latex`, makedoc:54; the `color` option needs a `color.cfg` naming a driver, flabels.dtx:109-112 and 771-777)
- Main file: flabels.dtx (the `driver` block at flabels.dtx:13-26 is the only `\documentclass`/`\begin{document}`; other samples: none; flabels.sty is not shipped, flabels.ins at flabels.ins:19 generates it from the dtx)
- Read: main yes, zip-local classes and styles all (the style's source is flabels.dtx, read in full; flabels.pdf not read)

## Verdict
no. The zip is the source of a small utility package whose whole output is a hand-drawn object (a ring-binder spine label: outline, "company" box, hole cross, ruled lines) built from `picture` commands, counters, conditionals and a `\loop`; no lib way expresses that, and the only candidate way is the package itself, which I did not accept as a way (see "Lib changes"). The sample is the ltxdoc driver; its own preamble and prose reduce to published ways, but its example figures reach into the package's `@` internals and reset them by hand. When unsure the rubric says no.

## Blockers
- `ART` the label drawing is the package's identity: outline, company box, hole marker, auxiliary lines, all `picture` (`\multiput`, `\line`, `\framebox`, `\put`) (flabels.dtx:839-847, 857-874, 900-911, 923-936)
- `BESPOKE` hand-rolled state that drives what is printed: `\newif` switches `\ifl@itz` `\iff@llheight` `\ifn@rrow` `\ifcolorl@bel` `\ifno@hole` (flabels.dtx:501-561), per-format constants set inside `\DeclareOption{leitz}` (502-511), `\full@height` and `\n@rrow` computing offsets (697-767), sp-to-mm conversion by `\divide ... by 186468` (587), `\loop ... \repeat` label copies (902-910)
- `BESPOKE` the sample body resets internals by hand to draw its figures at another scale: `\cnt@paperheight=297`, `\cnt@pictvoffset=5`, a re-made `\savebox{\theh@le}` (flabels.dtx:294-311, 374-393). Arguably content (figure artwork), but these are not in a float and they depend on unpublished `@` names, so I count it
- `UNMAPPED` component "binder spine label": no lib way, and the package itself is not accepted as one (flabels.dtx:76-79, 164-166)

Not blockers, recorded: `flabels.sty` must be generated by `tex flabels.ins` (docstrip, TeX only); the index needs the `makeindex` program with `gind.ist`, which README:42-44 lists but the zip does not ship (missing asset); `makedoc-patched:63` runs `sed -i` on `flabels.idx` as a workaround, and its header says the original script could not build the manual (makedoc-patched:3); the odd macro names `->fullheight`, `->narrow`, `->color` at flabels.dtx:688, 740, 770 are what the workaround is for.

## Content-opaque
The two `picture` illustrations of the documentation (flabels.dtx:294-361, 374-459) are content in spirit, but they sit in `center`, not a float, so I did not rely on that exemption (see blockers). Inline `$28.3 \times 31.8$` (flabels.dtx:77-79) is content.

## Lib changes
- New ways proposed: none. Considered and not proposed: `NEW:label.flabels` (the CTAN package `flabels` as a doc-kind way for binder labels). W1 passes (CTAN, lppl1). W2 passes in part (options `fullheight` `narrow` `color` `nohole` `nice` `a4paper`, lengths, colour names, `\company{...}`). W3 is doubtful: everything is hard-wired to one physical format, the 28.3 x 31.8 cm Leitz binder, and `leitz` is a dummy option (flabels.dtx:141-145, 502-511). W4 passes (`\usepackage[...]{flabels}` plus `\emptylabel{n}` and `\labeltext{...}`, flabels.dtx:900-936). I also did not want a package to count as its own way, since then every CTAN package zip would be a trivial `yes`. If the project decides otherwise, this file flips to `yes` with `NEW:label.flabels` and `class.ltxdoc`, the example pictures recorded as content-opaque, and the sample-internals blocker re-examined.
- Existing ways used for the first time by the lib: none needed (the consolidator computes this)
